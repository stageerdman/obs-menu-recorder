## Recently fixed, needs confirmation on real hardware/connection
- [ ] OneDrive uploads still failing on large files (fix 2026-09-23, follow-up to a4a9947):
      the timeout bump wasn't enough — real library.json failures were all mid-upload
      NSURLError transients (network-connection-lost, cannot-parse-response, timed-out) that
      each killed the whole upload with no retry, and the manual retry restarted from byte 0,
      so multi-hundred-MB / multi-GB files rarely finished across a flaky/slow upstream.
      OneDriveClient.uploadFile now retries each chunk up to maxChunkRetries (5) CONSECUTIVE
      failures with exponential backoff (capped 30s), resuming from the server's own
      nextExpectedRanges offset each time (Graph upload sessions are resumable). 4xx-non-429
      still fails fast; cancel still propagates. Confirm the previously-failed large files
      (Call Review - Miroslav, DealMakers Roleplay, Sales Call - Michal 2) now upload to
      completion — click the red exclamation-icloud icon to retry each.
    - Note (unrelated cosmetic): many uploaded entries have sizeBytes far smaller than
      cloudBytesSent in library.json, so the in-progress % bar denominator is wrong for
      those. Separate from the upload failures; not touched here.

## Known upstream limitations (no in-app fix)
- OBS quit-time crash (copy_audio_data segfault) — RecBar never quits OBS as a result.
- Camera "stuck open" after a real recording: RemoveInput can report success while the
  AVCaptureSession never tears down; only a manual OBS quit/relaunch clears it.
